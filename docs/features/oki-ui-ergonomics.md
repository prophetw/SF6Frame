# 压起身计算器 UI 易用性优化

## 功能目标

降低 `#/oki` 路由在移动端和长结果页中的浏览成本，让用户优先看到核心压起身匹配结果，同时保留循环投、另类压起身、时序图等进阶信息的完整访问能力。

## 核心入口

- `src/App.vue`
  - 移动端顶部导航改为品牌居中、链接横向滚动、语言选择固定在右侧。
- `src/views/OkiCalculatorView.vue`
  - 击倒预设支持搜索，默认只展示部分预设。
  - 自动匹配结果在移动端默认展示前 12 条，可手动展开其余结果。
  - 结果详情中的时序图默认不渲染，点击后再展开。
  - 循环投和另类压起身默认折叠，降低主结果页长度。
- `src/utils/okiPressure.ts`
  - 从打击范围和当前对手抢招发生反算可安全压制的起身帧范围。
  - 将角色击倒预设、自定义击倒按可复用的击倒优势分组。
- `src/components/OkiRouteMemory.vue`
  - 在桌面和移动端结果详情中展示同一路线可复用的击倒，帮助按路线记忆。
- `src/utils/wakeupDriveImpact.ts`
  - 复用项目既有 DI 的 `26F` 发生、`2F` 持续数据，计算能否收招后直接格挡起身 DI。
- `src/utils/wakeupInvincible.ts`
  - 独立估算起身无敌技的收招安全性，并限制额外绿冲骗招的推荐窗口。

## 架构关系

保留压起身、循环投、绿冲、迸放、安全骗压等原有匹配逻辑，新增安全范围和防 DI 的派生结果，并调整列表与详情展示。

`OkiCalculatorView.vue` 继续负责页面状态、筛选和结果展示。`allOkiResults` 为已匹配路线附加安全压制范围和 DI 收招判断；速记分组与折叠状态只影响展示，不改变压制、相杀、空挥等原有判定。

## 数据流

1. 角色数据加载后生成完整击倒预设 `knockdownMoves`。
2. `knockdownSearchQuery` 过滤完整预设，`visibleKnockdownMoves` 决定当前展示数量。
3. 压起身计算仍生成完整排序结果 `okiResults`。
4. 移动端卡片使用 `visibleOkiResults` 展示前 12 条，用户点击后切换 `showAllAutoResults`。
5. 时序图由 `showResultTimeline` 和 `showThrowTimeline` 控制是否渲染。
6. 循环投和另类压起身分别由 `showThrowSection`、`showAltOkiSection` 控制折叠状态。
7. 自动匹配结果增加当前起身帧、可安全压制范围；结果详情将范围传给速记组件，与当前角色的完整击倒预设、自定义击倒比较。

## 可安全压制范围与速记

列表“打击时序”的主行表示我方攻击实际有判定的范围，次行表示发生帧。“起身帧”是对手首个可动帧，等于击倒优势 `N + 1`。“适用起身范围”列表示：保持同一动作路线时，哪些对手起身时机可以被这条路线抢先打断普通抢招。

设我方连续打击范围为 `[A, B]`，对手普通抢招发生为 `R`，对手起身首帧为 `W`。抢招判定首帧是 `W + R - 1`，安全压制必须同时满足 `A < W + R - 1`、`W <= B`，因此：

- 可安全压制起身范围：`[max(1, A - R + 2), B]`。
- 可复用击倒优势范围：将起身范围两端各减 `1`。
- `R <= 1` 时没有抢招判定前的可命中窗口，不显示安全压制范围。
- 同帧相杀不计入安全范围；“安全”仅指抢先打断普通抢招，不能用于判断无敌技或距离。
- 多段攻击继续沿用现有匹配所使用的有效打击段，不额外跨越无判定间隔。
- 隆波动拳继续采用已有的版边接触标定范围，并叠加前置帧；不从当前接触帧推测飞行道具持续时间。

例如打击 `31~34F`、对手抢招 `4F`，可安全压制起身 `29~34F`，对应 `+28~+33F` 击倒。起身 `28F` 时对手在 `31F` 出判定，属于相杀边界；`+28F` 击倒则在 `29F` 起身，可以被压制。

结果详情的“速记：一套路线，多个击倒”将满足范围的击倒按优势帧分组，包括角色原始数据中的条件击倒和自定义连招预设。建议记“收尾招式 / 前置节奏 / 击倒优势区间”，而不是逐条死记。分组只是时机复用，距离、版边等条件仍需满足原路线要求；换击倒后被防与命中优势可能变化。

## 防 DI 列

斗气迸放（Drive Impact / DI）与起身斗反分开显示。表头将原来的“安全”明确为“防斗反”，另加“防 DI”；移动端也独立显示两种信息。

本列采用收招后直接格挡的帧数估算：HPHK（DI）的原始发生数据保留为 `26F`；按用户实测确认的计帧口径，与“另类压起身”的 DI 路线统一使用相加公式，起身基准帧 `W` 对应首次判定 `W + 26`，不再额外减 `1`。例如基准帧为 `1F` 时，第 `27F` 生效。我方沿用现有路线的恢复时刻 `recoverFrame`，若不晚于 DI 判定首帧则显示“可防”，否则显示“不可直防”。详情和提示显示恢复帧、生效帧与余量。边界相等表示恰好能防，没有额外余量。

- DI 常量统一由 `DRIVE_IMPACT` 提供，“另类压起身”的 DI 对齐功能也读取同一份常量。
- 持续或收招数据缺失时显示“未确认”，不把解析回退值当作安全保证；隆波动拳使用已有的本体恢复公式。
- 此列不模拟护甲接触停顿、取消反 DI、多段破甲、距离和资源；“不可直防”不代表没有其他应对，“可防”也不代表在版边格挡安全。
- 示例：隆绿冲 `6MP` 在现有模型中 `54F` 恢复。`+27F` 击倒对应页面起身帧 `28F`，DI 在 `28 + 26 = 54F` 生效，恰好可防；`+26F` 击倒对应页面起身帧 `27F`，DI 在 `53F` 生效，不可直接收招格挡；`+28F` 击倒时 DI 在 `55F` 生效，有 `1F` 余量。

## 防无敌列与额外绿冲骗招

自动匹配新增「防 5F 无敌」列，移动端提供对应标签与详情。无敌启动默认 `5F`，可在列表上方单独调整，不使用或改变普通抢招的发生帧参数，也不改变 DI、斗反或进阶「安全骗压」面板的既有计算。

按本功能约定，设对手起身帧为 `W`，无敌启动为 `S`，无敌生效帧为 `I = W + S`。动作总耗时 `T = 前置动作 + 绿冲偏移（如有，11F）+ 招式空挥总帧`，其中 `T` 表示动作占用的最后一帧，与既有 DI 使用的首个恢复帧区分。招式总帧复用 `frameTotals.ts`，优先计算 `startup - 1 + active + whiffRecovery`，支持已有总帧回退；隆波动拳沿用本体总帧。

- 安全条件：`T < I`，收招后立即拉防。
- 最晚安全收招：`I - 1`；安全余量：`I - 1 - T`。
- 余量大于 `0` 显示绿色「安全 · 余 NF」；等于 `0` 显示黄色「极限 · 余 0F」；负数显示红色「不安全」；总帧未知显示「未确认」。
- 示例：击倒 `+28F`，`W = 29`，`I = 34`；`T = 31` 余 `2F`，`T = 33` 为极限，`T = 34` 不安全。

现有压制、相杀、空挥结果直接附加本列。额外只补充原本不满足这三类匹配、且在 `[max(1, W - 3), I - 1]` 内结束动作的绿冲路线；不把所有满足安全上限的早收招动作加入列表。`+28F` 示例的推荐收招窗口为 `26～33F`，大击倒的窗口随起身时机后移。

额外路线同时标记「空挥」「骗招」，不设压制成功、命中、被防与 Meaty 收益。「空挥先动」沿用既有口径：`对手起身帧 − 我方恢复帧`；恢复帧是收招后首个可行动帧。正数表示我方先动，`0F` 表示同时恢复，负数表示对手先动，负数用红色显示。例：`+28F` 击倒后起身 `29F`，绿冲 `5LK` 在 `29F` 结束、`30F` 恢复，空挥先动为 `-1F`，但仍能防本功能约定的 `34F` 生效无敌技。桌面与移动端详情均显示相减公式。

这些路线复用现有前置动作枚举、搜索、喜好与排除设置。默认按被防排序时，额外骗招排在原有匹配之后，优先遵循喜好，再按安全余量从多到少排列；点击其他列时整表按所选列排序。原有结果保留前 `50` 条，额外骗招默认展示 `5` 条，其余通过「展开其余 N 条骗招」查看。「只看安全骗招」筛选保留所有 `canBlock === true` 的已有或新增路线，排除不安全与未确认结果。

该功能只作帧数估算，假定收招后立即防御；不模拟距离、无敌投及游戏内具体碰撞效果。

## 列表信息布局

- “发生”和“打击帧”合并为“打击时序”：主行显示打击范围，次行显示发生帧，保留按打击首帧排序。
- “空挥先动”独立放在容错之后，显示空挥收招到对手起身之间的先动帧数；组合栏仅显示“空挥”类型，命中、被防等不适用字段继续显示 `-`。
- “可安全压制”表头改为“适用起身范围”，上方常驻起身帧和对手抢招发生摘要，详细计算规则默认折叠在“计算说明”。
- 组合主行放喜好星标、路线类型、动作及指令；版边、连锁取消等条件放在次行，避免与动作名称混排。移动端采用相同的信息层次。
- 防斗反不能恢复格挡时明确显示红色“不可防”，与无数据或不适用的 `-` 区分。

## 关键数据结构

- `knockdownSearchQuery`：击倒预设搜索关键字。
- `showAllKnockdownPresets`：控制击倒预设是否展示全部。
- `showAllAutoResults`：控制移动端自动匹配结果是否展示全部。
- `showResultTimeline` / `showThrowTimeline`：控制时序图是否渲染。
- `showThrowSection` / `showAltOkiSection`：控制进阶面板折叠状态。
- `visibleKnockdownMoves`、`visibleOkiResults`、`visibleThrowResults` 等：展示层派生列表。

## 外部依赖或 API

本功能不调用外部服务，不新增依赖。浏览器验证使用项目已有的 `puppeteer` 依赖和本地 Vite 开发服务。

## 异常路径

- 击倒搜索无匹配结果：展示空状态，不影响已选击倒。
- 展示列表被折叠：完整计算结果仍保留在内存中，用户展开后继续查看。
- 时序图未展开：不会渲染时间轴 DOM，避免长详情默认撑高页面。
- 移动端导航链接超出宽度：通过横向滚动访问，不产生页面级横向滚动。
